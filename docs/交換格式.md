# 個人記帳本 API 資料交換格式規範（步驟 14）

本文件定義個人記帳本系統（`ledger-api`）之前後端資料交換格式標準，供前端客戶端與外部系統對接使用。前端與客戶端無須查閱個別後端路由程式碼，一律遵循本文件所約定之協定。

> **註記**：本文件所有範例中的資料列主鍵 `id` 一律以數字 `1` 起算展示，實際執行時請以伺服器端資料庫自動遞增建立回傳的實體 `id` 為準。

---

## 一、 共通規則

### 1. 頂層回應結構（Three Keys）
所有 HTTP API 回應主體一律為標準 JSON 物件，固定包含以下三個頂層鍵：

| 鍵名 | 型別 | 說明 |
| :--- | :--- | :--- |
| `code` | `Integer` | HTTP 狀態碼（與 HTTP Header 之狀態碼一致，如 200、201、400、404、500）。 |
| `message` | `String` | 面向前端使用者的繁體中文人話訊息，說明處理結果或錯誤原因，**嚴禁暴露資料庫表名、約束名、SQL 語法或內部堆疊**。 |
| `data` | `Object` / `Array` / `null` | 業務資料主體。成功查詢時為物件或陣列；失敗或錯誤（4xx、5xx）時固定為 `null`。 |

**頂層基本樣板**：
```json
{
  "code": 200,
  "message": "處理成功",
  "data": {}
}
```

### 2. HTTP 狀態碼對照表

| 狀態碼 | 意義 | 適用情境 | `data` 內容 |
| :--- | :--- | :--- | :--- |
| **`200 OK`** | 成功 | 資料查詢成功、更新成功或計算完成。若清單無資料，亦回傳 200 與空陣列 `[]`。 | 物件、陣列或計算結果 |
| **`201 Created`** | 已建立 | 資源新增成功。 | 剛寫入資料庫之該筆實體資料列 |
| **`400 Bad Request`** | 請求錯誤 | 必填欄位缺漏、格式驗證失敗、數值小於或等於 0、唯一值衝突（如名稱或號碼重複）、外鍵參照不存在、或業務邏輯不符（如賣出超額）。 | `null` |
| **`404 Not Found`** | 找不到資源 | 請求 URL 路徑中的資源識別碼（ID）於資料庫中不存在。 | `null` |
| **`500 Internal Error`**| 伺服器內部錯誤 | 資料庫連線異常、暫時斷線或系統未預期錯誤。 | `null` |

### 3. 客戶端不送的欄位
下列欄位由伺服器端與資料庫自動維護，**客戶端在新增（POST）或更新（PATCH）時不可傳入**；若傳入將被伺服器忽略或拒絕：
- **`id`**：代理整數主鍵（64 位元 BIGINT），由資料庫自動遞增建立，客戶端不可手動指定或修改。
- **`created_at`**：記錄建立時間，由資料庫在 INSERT 時預設填入當前 UTC 時間。
- **`updated_at`**：記錄最後修改時間，由後端在 PATCH 更新成功時明確寫入當前 UTC 時間。

### 4. 日期、時間與數值型別規範
- **日期（Date）**：格式固定為 ISO 8601 標準字串 `YYYY-MM-DD`（如 `"2026-08-15"`、`"2026-11-14"`）。
- **審計時間戳（Timestamp）**：格式固定為 ISO 8601 帶 UTC 時區之字串 `YYYY-MM-DDTHH:MM:SS.ffffff+00:00`。
- **金額與數值（Amount / Quantity / Price / FX Rate / Ratio / Fee / Tax）**：
  - 在 JSON 交換格式中表示為數值（`Number`，如浮點數或整數）。
  - 後端內部皆以高精度定點數（`Numeric(16, 4)` 或 `Numeric(12, 6)`）計算與儲存，避免 IEEE 754 浮點數誤差。
- **貨幣代碼（Currency）**：ISO 4217 標準三碼大寫英文字母，如 `"TWD"`、`"USD"`、`"JPY"`。

### 5. 可空欄位之表現
當資料表中之欄位允許為空（Nullable）且無實質內容時，API 回應中該欄位之值**固定以 JSON `null` 出現**，絕不省略該鍵，以維持前端型別介面的一致性。例如：`"settled_on": null`、`"note": null`、`"invoice_id": null`。

## 二、 查詢參數（Query Parameters）彙整

查詢端點皆支援標準 HTTP GET 查詢參數，參數值於後端一律以參數化綁定（Parameterized Queries）傳送給資料庫，杜絕 SQL 注入：

| 端點 | 參數名稱 | 參數型別 | 必填 / 選填 | 說明與格式 |
| :--- | :--- | :--- | :--- | :--- |
| `GET /api/incomes` | `account_id` | `Integer` | 選填 | 篩選指定入帳帳戶 ID |
| | `category_id` | `Integer` | 選填 | 篩選指定入帳分類 ID |
| | `date_from` | `String` | 選填 | 篩選入帳起始日期（含），格式 `YYYY-MM-DD` |
| | `date_to` | `String` | 選填 | 篩選入帳結束日期（含），格式 `YYYY-MM-DD` |
| `GET /api/expenses` | `account_id` | `Integer` | 選填 | 篩選指定扣款帳戶 ID |
| | `category_id` | `Integer` | 選填 | 篩選指定花費分類 ID |
| | `invoice_id` | `Integer` | 選填 | 篩選所關聯之發票 ID |
| | `date_from` | `String` | 選填 | 篩選消費起始日期（含），格式 `YYYY-MM-DD` |
| | `date_to` | `String` | 選填 | 篩選消費結束日期（含），格式 `YYYY-MM-DD` |
| `GET /api/invoices` | `period_key` | `String` | 選填 | 篩選開立所屬期別，格式為雙月期初 `YYYY-MM`（如 `2026-07`） |
| | `prize_status`| `String` | 選填 | 篩選對獎狀態：`unchecked`、`lost`、`won`、`claimed`、`void` |
| `GET /api/trades` | `instrument_id`| `Integer`| 選填 | 篩選指定投資標的 ID |
| | `account_id` | `Integer` | 選填 | 篩選指定交割/扣款帳戶 ID |
| `GET /api/summary` | `month` | `String` | **必填** | 指定統計之西元月份，格式 `YYYY-MM`（例如 `2026-08`、`2026-11`） |

## 三、 各資源交換格式與成功範例

### 1. 帳戶（Account）
記錄實體或虛擬資金載體（現金皮夾、銀行、信用卡、券商交割戶等）。

#### 成功回應範例（現金錢包）
```json
{
  "code": 201,
  "message": "帳戶新增成功",
  "data": {
    "id": 1,
    "name": "現金錢包",
    "kind": "cash",
    "currency": "TWD",
    "opening_balance": 0.0,
    "statement_day": null,
    "payment_day": null,
    "created_at": "2026-08-01T08:00:00.000000+00:00",
    "updated_at": "2026-08-01T08:00:00.000000+00:00"
  }
}
```

#### 欄位定義表
| 欄位名稱 | 型別 | 可否為空 | 說明 |
| :--- | :--- | :--- | :--- |
| `id` | `Integer` | 否 | 帳戶唯一識別碼（由資料庫自增） |
| `name` | `String` | 否 | 帳戶名稱（全系統唯一不可重複） |
| `kind` | `String` | 否 | 帳戶類別：`cash`（現金）、`bank`（銀行）、`credit_card`（信用卡）、`broker`（券商交割戶） |
| `currency` | `String` | 否 | 帳戶基礎幣別（三碼，預設 `"TWD"`） |
| `opening_balance` | `Number` | 否 | 開帳起始餘額（預設 `0.0`） |
| `statement_day` | `Integer` | 是 | 信用卡結帳日（1 至 31），非信用卡為 `null` |
| `payment_day` | `Integer` | 是 | 信用卡繳款日（1 至 31），非信用卡為 `null` |
| `created_at` | `String` | 否 | 資料建立時間（UTC ISO 8601） |
| `updated_at` | `String` | 否 | 資料最後更新時間（UTC ISO 8601） |

### 2. 帳戶餘額（Account Balance）
端點：`GET /api/accounts/<int:account_id>/balance`。唯讀計算帳戶當前總資產。

#### 成功回應範例
```json
{
  "code": 200,
  "message": "取得帳戶餘額成功",
  "data": {
    "account_id": 1,
    "name": "現金錢包",
    "currency": "TWD",
    "opening_balance": 0.0,
    "balance": 230.0,
    "balance_twd": 230.0,
    "original_currency_balance": 230.0,
    "twd_balance": 230.0
  }
}
```

#### 欄位定義表
| 欄位名稱 | 型別 | 說明 |
| :--- | :--- | :--- |
| `account_id` | `Integer` | 帳戶識別碼 |
| `name` | `String` | 帳戶名稱 |
| `currency` | `String` | 帳戶幣別 |
| `opening_balance` | `Number` | 初始開帳餘額 |
| `original_currency_balance` | `Number` | 原幣別即時餘額（開帳 + 轉入 - 轉出 + 入帳 - 花費 + 交易款項） |
| `twd_balance` | `Number` | 折合新台幣總餘額（各筆交易依發生匯率即時折算加總） |

---

### 3. 帳戶移轉（Transfer）
記錄內部帳戶間的資金移轉與換匯。端點：`/api/transfers`。

#### 成功回應範例（轉帳 200）
```json
{
  "code": 201,
  "message": "移轉新增成功",
  "data": {
    "id": 1,
    "transferred_on": "2026-08-05",
    "amount": 200.0,
    "currency": "TWD",
    "fx_rate_to_twd": 1.0,
    "from_account_id": 1,
    "to_account_id": 2,
    "note": "錢包領錢轉入銀行",
    "created_at": "2026-08-05T09:30:00.000000+00:00",
    "updated_at": "2026-08-05T09:30:00.000000+00:00"
  }
}
```

#### 欄位定義表
| 欄位名稱 | 型別 | 可否為空 | 說明 |
| :--- | :--- | :--- | :--- |
| `id` | `Integer` | 否 | 移轉唯一識別碼 |
| `transferred_on` | `String` | 否 | 移轉日期（`YYYY-MM-DD`） |
| `amount` | `Number` | 否 | 移轉金額（必須大於 0） |
| `currency` | `String` | 否 | 移轉幣別（三碼英文字母） |
| `fx_rate_to_twd` | `Number` | 否 | 折合台幣匯率（台幣固定為 1.0） |
| `from_account_id`| `Integer` | 否 | 轉出帳戶 ID（限制不可與轉入帳戶相同） |
| `to_account_id` | `Integer` | 否 | 轉入帳戶 ID |
| `note` | `String` | 是 | 備註說明，無備註時為 `null` |
| `created_at` | `String` | 否 | 建立時間戳 |
| `updated_at` | `String` | 否 | 更新時間戳 |

### 4. 入帳分類（IncomeCategory）與入帳記錄（Income）
記錄正向現金流流入帳戶的明細。端點：`/api/income-categories`、`/api/incomes`。

#### 成功回應範例（十一月薪水 500）
```json
{
  "code": 201,
  "message": "入帳記錄新增成功",
  "data": {
    "id": 1,
    "received_on": "2026-11-05",
    "amount": 500.0,
    "currency": "TWD",
    "fx_rate_to_twd": 1.0,
    "category_id": 1,
    "account_id": 1,
    "source": "公司",
    "note": "十一月薪水",
    "invoice_id": null,
    "trade_id": null,
    "created_at": "2026-11-05T02:00:00.000000+00:00",
    "updated_at": "2026-11-05T02:00:00.000000+00:00"
  }
}
```

#### 欄位定義表（入帳記錄 `incomes`）
| 欄位名稱 | 型別 | 可否為空 | 說明 |
| :--- | :--- | :--- | :--- |
| `id` | `Integer` | 否 | 入帳唯一識別碼 |
| `received_on` | `String` | 否 | 入帳日期（`YYYY-MM-DD`） |
| `amount` | `Number` | 否 | 入帳金額（必須大於 0） |
| `currency` | `String` | 否 | 幣別代碼（如 `"TWD"`） |
| `fx_rate_to_twd` | `Number` | 否 | 折合台幣匯率（必須大於 0） |
| `category_id` | `Integer` | 否 | 所屬入帳分類 ID（外鍵關聯 `income_categories`） |
| `account_id` | `Integer` | 否 | 收款帳戶 ID（外鍵關聯 `accounts`） |
| `source` | `String` | 是 | 來源（如發送單位或雇主）。`source` 與 `note` 不可同時為空 |
| `note` | `String` | 是 | 備註說明。`source` 與 `note` 不可同時為空 |
| `invoice_id` | `Integer` | 是 | 關聯中獎發票 ID（唯一約束，一張發票僅限產生一筆入帳） |
| `trade_id` | `Integer` | 是 | 關聯投資交易 ID（唯一約束，一筆現金股利交易僅限產生一筆入帳） |
| `created_at` | `String` | 否 | 建立時間戳 |
| `updated_at` | `String` | 否 | 更新時間戳 |

### 5. 統一發票（Invoice）與發票品項（InvoiceItem）
記錄台灣統一發票主檔與掛載之明細品項。端點：`/api/invoices`、`/api/invoices/<id>/items`。

#### 成功回應範例（單筆發票含品項與花費 ID 清單，發票號碼 `AB12345678`）
```json
{
  "code": 200,
  "message": "取得發票成功",
  "data": {
    "id": 1,
    "number": "AB12345678",
    "issued_on": "2026-08-15",
    "amount": 70.0,
    "kind": "electronic",
    "currency": "TWD",
    "fx_rate_to_twd": 1.0,
    "random_code": "1234",
    "seller_name": "便當店",
    "seller_ban": "12345678",
    "prize_status": "unchecked",
    "period_key": "2026-07",
    "items": [
      {
        "id": 1,
        "invoice_id": 1,
        "name": "排骨便當",
        "quantity": 1.0,
        "unit_price": 70.0,
        "line_amount": 70.0,
        "created_at": "2026-08-15T04:10:00.000000+00:00",
        "updated_at": "2026-08-15T04:10:00.000000+00:00"
      }
    ],
    "expense_ids": [1],
    "created_at": "2026-08-15T04:00:00.000000+00:00",
    "updated_at": "2026-08-15T04:00:00.000000+00:00"
  }
}
```

#### 欄位定義表（統一發票 `invoices`）
| 欄位名稱 | 型別 | 可否為空 | 說明 |
| :--- | :--- | :--- | :--- |
| `id` | `Integer` | 否 | 發票唯一識別碼 |
| `number` | `String` | 否 | 發票號碼（格式：兩碼大寫英文加八碼數字，如 `"AB12345678"`，全系統唯一） |
| `issued_on` | `String` | 否 | 開立日期（`YYYY-MM-DD`） |
| `amount` | `Number` | 否 | 發票總金額（大於 0） |
| `kind` | `String` | 否 | 發票種類：`paper`（紙本）、`electronic`（電子發票） |
| `currency` | `String` | 否 | 幣別（預設 `"TWD"`） |
| `fx_rate_to_twd` | `Number` | 否 | 匯率（台幣預設 `1.0`） |
| `random_code` | `String` | 是 | 隨機碼（可空，若有值為四碼數字字串） |
| `seller_name` | `String` | 是 | 賣方店家名稱，可為 `null` |
| `seller_ban` | `String` | 是 | 賣方統一編號（8 碼數字），可為 `null` |
| `prize_status` | `String` | 否 | 對獎狀態：`unchecked`（未對獎）、`lost`（未中獎）、`won`（已中獎）、`claimed`（已兌獎）、`void`（已作廢） |
| `period_key` | `String` | 否 | 所屬開獎期別（雙月期初，如 7-8 月為 `"2026-07"`） |
| `items` | `Array` | 否 | 掛載之明細品項清單（`GET /api/invoices/<id>` 單筆回傳） |
| `expense_ids` | `Array` | 否 | 關聯此張發票之花費 ID 清單（`GET /api/invoices/<id>` 單筆回傳） |

### 6. 開獎期別（DrawPeriod）與開獎獎項（DrawPrize）
記錄統一發票開獎期別標識與該期中獎號碼與獎金。端點：`/api/draw-periods`。

#### 成功回應範例（2026-07 期開獎獎項設定）
```json
{
  "code": 201,
  "message": "開獎獎項新增成功",
  "data": {
    "id": 1,
    "draw_period_id": 1,
    "tier": "sixth",
    "matching_number": "678",
    "amount": 200.0,
    "created_at": "2026-09-25T05:30:00.000000+00:00",
    "updated_at": "2026-09-25T05:30:00.000000+00:00"
  }
}
```

#### 成功回應範例（執行整期發票批次對獎 `POST /api/draw-periods/1/check`）
```json
{
  "code": 200,
  "message": "對獎完成，共對了 1 張發票，中獎 1 張",
  "data": {
    "checked_count": 1,
    "won_count": 1
  }
}
```

#### 欄位定義表（開獎獎項 `draw_prizes`）
| 欄位名稱 | 型別 | 可否為空 | 說明 |
| :--- | :--- | :--- | :--- |
| `id` | `Integer` | 否 | 獎項識別碼 |
| `draw_period_id` | `Integer` | 否 | 所屬開獎期別 ID（CASCADE 隨期別刪除） |
| `tier` | `String` | 否 | 獎項級別：`special`、`grand`、`first`、`second`、`third`、`fourth`、`fifth`、`sixth`、`extra_sixth` |
| `matching_number`| `String` | 否 | 中獎號碼（`special`、`grand`、`first` 必須為 8 碼；其他獎項為 3 至 8 碼） |
| `amount` | `Number` | 否 | 該獎項法定獎金金額（大於或等於 0） |

#### 欄位定義表（花費記錄 `expenses`）

## 四、 錯誤回應格式範例

當客戶端請求違反規則或資源不存在時，伺服器一律回傳標準三鍵錯誤物件，`data` 嚴格為 `null`，`message` 採用固定人話句子：

### 1. HTTP 400 Bad Request（資料驗證失敗）
適用於參數缺漏、數值小於或等於 0、唯一值名稱重複、外鍵指向不存在等業務約束違規。

```json
{
  "code": 400,
  "message": "資料驗證失敗或違反約束規則",
  "data": null
}
```

### 2. HTTP 404 Not Found（找不到指定的資源）
適用於 URL 路徑中指定之資源 ID（如 `/api/accounts/999`）於資料庫中不存在。

```json
{
  "code": 404,
  "message": "找不到指定的資源",
  "data": null
}
```

## 五、 內部錯誤與日誌規範（Internal Errors & Logging）

為保護系統架構安全並防止資訊洩漏，**所有資料庫細節、約束名稱、資料表名稱、SQLSTATE 代碼、例外類別名稱與 Python 錯誤堆疊，嚴格僅記錄於後端伺服器內部日誌檔案，絕不出現在回傳給前端的 HTTP JSON 中**。

### 1. 內部日誌物件的鍵定義
當伺服器攔截到錯誤時，結構化寫入內部日誌系統的 JSON 物件結構：

| 鍵名 | 型別 | 說明 |
| :--- | :--- | :--- |
| `timestamp` | `String` | 發生錯誤之 UTC 時間戳（ISO 8601） |
| `level` | `String` | 日誌等級：`WARNING`、`ERROR`、`CRITICAL` |
| `request_id` | `String` | 本次 HTTP 請求之追蹤唯一識別碼（UUID） |
| `method` | `String` | HTTP 請求方法（如 `POST`、`PATCH`、`GET`） |
| `path` | `String` | HTTP 請求路徑（如 `/api/accounts`、`/api/trades/1/void`） |
| `error_code` | `String` | 內部標準化錯誤代碼，詳見下表 |
| `message` | `String` | 伺服器內部詳細診斷訊息 |
| `table` | `String` | 觸發錯誤或衝突之資料庫表名 |
| `constraint_name` | `String` | 被違反之資料庫約束識別碼 |
| `sqlstate` | `String` | PostgreSQL 標準 5 碼 SQLSTATE 代碼（如 `23505`、`23503`、`23514`） |
| `exception` | `String` | 捕捉到的 Python / SQLAlchemy 例外名稱（如 `IntegrityError`） |
| `detail` | `String` | 資料庫驅動層回傳之詳細底層文字 |

### 2. 內部 `error_code` 對照表

| `error_code` | 對應 SQLSTATE / 狀況 | 內部說明 | 對外 HTTP 狀態碼與人話 |
| :--- | :--- | :--- | :--- |
| **`conflict.unique_name`** | `23505` (Unique Violation) | 名稱已存在，違反唯一約束（如帳戶、分類、標的） | 400（名稱已存在，不可重複） |
| **`conflict.duplicate_invoice_number`** | `23505` | 發票號碼重複（`uq_invoices_number`） | 400（發票號碼已存在，不可重複） |
| **`conflict.duplicate_trade_id`** | `23505` | 該筆交易已被綁定入帳（`uq_incomes_trade_id`） | 400（此交易已產生入帳記錄，不可重複入帳） |
| **`conflict.duplicate_period_key`** | `23505` | 開獎期別已存在（`uq_draw_periods_period_key`） | 400（該開獎期別已存在，不可重複建立） |
| **`conflict.duplicate_prize`** | `23505` | 同期重複設定相同獎號（`uq_draw_prizes_...`） | 400（該期已存在相同的獎項與中獎號碼） |
| **`validation.amount_positive`** | `23514` (Check Violation) | 金額或數值未大於 0（`CHECK (amount > 0)`） | 400（金額必須大於 0） |
| **`validation.fx_rate_positive`** | `23514` | 折合台幣匯率未大於 0（`CHECK (fx_rate_to_twd > 0)`）| 400（折合台幣匯率必須大於 0） |
| **`validation.source_note_required`** | `23514` | 來源與備註皆為空（`CHECK (source IS NOT NULL OR ...)`）| 400（來源與備註不可同時為空，至少需填寫一項） |
| **`validation.holding_insufficient`** | 業務邏輯校驗失敗 | 賣出股數或減資股數大於目前有效庫存 | 400（賣出數量超過目前持有數量） |
| **`foreign_key.not_found`** | 應用層預檢 / `23503` | 外鍵參照之父列不存在（如分類、帳戶、發票、標的） | 400（指定之分類/帳戶不存在） |
| **`foreign_key.restrict`** | `23503` (Foreign Key Violation) | 父列仍被子列參照，拒絕刪除（`ON DELETE RESTRICT`） | 400（資料仍被其他記錄參照，無法執行操作） |
| **`not_found.resource`** | 查無資料列 | 請求主鍵 ID 不存在 | 404（找不到指定的資源） |
| **`database.operational_error`** | `08006` / `08001` 等 | PostgreSQL 資料庫連線失敗或中斷 | 500（資料庫連線失敗，請稍後再試） |

以下為帳戶名稱重複時，伺服器內部記錄之日誌檔案條目範例（**前端回應僅會收到標準 400 人話訊息**）：

## 六、 與現況的差異

本節逐條對比目前後端程式實作與步驟 14 約定之差異與銜接細節：

1. **帳戶餘額回傳欄位（`GET /api/accounts/<id>/balance`）**：
   - **現況**：後端回傳的 `data` 同時提供新舊兼容欄位，包含 `balance`、`balance_twd`、`original_currency_balance`、`twd_balance`。
   - **步驟 14 約定**：前端核心規格重點讀取 `original_currency_balance`（原幣別餘額）與 `twd_balance`（台幣餘額）。現況完全涵蓋約定欄位，前端可直接取用 `twd_balance` 與 `original_currency_balance`。

2. **發票單筆查詢關聯欄位（`GET /api/invoices/<id>`）**：
   - **現況**：後端於單筆發票查詢時，在 `data` 內展開品項清單 `items`、關聯花費 ID 清單 `expense_ids`，並附帶開立日推導之期別 `period_key`。
   - **步驟 14 約定**：發票單筆查詢需包含品項清單與已掛上的花費 ID 清單。兩者規格完全相符。

3. **發票作廢與修改約定（`PATCH /api/invoices/<id>`）**：
   - **現況**：發票無備註欄位（未發明備註欄位），僅允許修改賣方資訊與隨機碼；`prize_status` 僅允許設為 `"void"`（作廢），若試圖修改號碼或主鍵則明確回傳 `400`。
   - **步驟 14 約定**：不可修改號碼與主鍵，無備註欄位，僅可將狀態修改為作廢。兩者規格完全相符。

4. **投資交易作廢（`POST /api/trades/<id>/void`）**：
   - **現況**：交易已有關聯入帳時，端點以 `400` 拒絕作廢，訊息為「此交易已有入帳記錄，無法作廢」，未建立入帳之交易可正常寫入 `voided_at`。
   - **步驟 14 約定**：已有入帳之交易不可作廢，需回傳 400。兩者規格完全相符。

5. **錯誤處理人話訊息粒度**：
   - **現況**：個別路由具備明確的中文語意提示（如「賣出數量超過目前持有數量」、「發票號碼已存在，不可重複」）；未被個別路由預檢而由全域例外處理器捕捉之底層 IntegrityError，則統一回傳「資料驗證失敗或違反約束規則」。
   - **步驟 14 約定**：對外回應統一不含資料庫表名與約束名，固定回傳繁體中文人話訊息。兩者完全一致。
