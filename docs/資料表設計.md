# 個人記帳系統資料表設計說明書

本文件為個人記帳系統（基於 Supabase PostgreSQL）之資料庫架構設計說明。系統專為個人獨立使用設計，不包含多使用者或帳號體系。後續將由後端應用程式（Flask 與 SQLAlchemy）進行讀寫操作。本設計著重於資料完整性、財務計算嚴謹性與關聯防護。

---

## 一、 全域設計規範與約束原則

1. **命名規範**：
   - 資料表與欄位名稱一律使用小寫英文，單字之間以底線（`snake_case`）連接。
   - 欄位命名具備自我解釋性，布林值欄位以 `is_` 為前綴。

2. **主鍵與外鍵規範**：
   - 所有資料表的主鍵（`id`）一律為資料庫自動遞增產生且建立後不可變更的 64 位元整數（PostgreSQL `BIGINT GENERATED ALWAYS AS IDENTITY`）。
   - 外鍵（Foreign Key）刪除約束：所有外鍵在父列仍被子列參照時，嚴格禁止刪除父列（PostgreSQL `ON DELETE RESTRICT`）。
   - **唯一例外**：發票品項明細表（`invoice_items`）從屬於統一發票表（`invoices`），當發票刪除時，其所屬品項一併消失（`ON DELETE CASCADE`）。

3. **審計時間戳（Audit Timestamps）**：
   - 每一張資料表皆包含 `created_at` 與 `updated_at` 兩欄位。
   - `created_at`：類型為 `timestamptz`，必填（NOT NULL），插入新資料時由資料庫預設填入 UTC 時間（`DEFAULT (CURRENT_TIMESTAMP AT TIME ZONE 'UTC')`）。
   - `updated_at`：類型為 `timestamptz`，必填（NOT NULL），資料列更新時由後端應用程式（API）明確寫入當前 UTC 時間。

4. **數值、幣別與匯率規範**：
   - **金額（Amount）**：採用可含小數的定點數 `NUMERIC(16, 4)`，避免浮點數誤差，滿足外幣或極小單位記帳需求。
   - **幣別（Currency）**：採用 ISO 4217 標準三碼大寫英文字母（`CHAR(3)`），如 `TWD`、`USD`、`JPY`。
   - **匯率（Exchange Rate）**：欄位名稱為 `exchange_rate_to_twd`，型態為 `NUMERIC(12, 6)`，必填（NOT NULL）。記錄交易發生當下折算為新台幣（TWD）之匯率。若交易原幣別即為 `TWD`，該匯率值固定為 `1.000000`。

5. **不具可變性計算值**：
   - 帳戶餘額、投資標的持有股數與平均持有成本，**絕不**建立為實體可修改之欄位，以徹底杜絕帳實不符與資料競態條件（Race Condition）。所有數值皆由各冊流水交易列即時聚合計出。

6. **約束表達劃分**：
   - 結構完整性（如外鍵、非空、唯一值、正規表示法格式檢查、常態數值邊界）：在 PostgreSQL 資料表層級以 `CHECK`、`UNIQUE`、`FOREIGN KEY` 約束表達。
   - 跨列複合業務規則（如賣出時總持股不可小於零、信用卡結帳日聯動邏輯）：明確標註為「**由 API 在寫入前檢查**」，後端於資料庫交易（Transaction）內透過鎖定機制驗證後寫入。

## 二、 資料表詳細設計

系統涵蓋四本帳冊（入帳、花費、投資、發票）與底層帳戶體系，共設計 10 張資料表：
1. `accounts`（帳戶表）
2. `account_transfers`（帳戶移轉表）
3. `income_categories`（入帳分類表）
4. `incomes`（入帳記錄表）
5. `expense_categories`（花費分類表）
6. `expenses`（花費記錄表）
7. `investment_assets`（投資標的表）
8. `investment_transactions`（投資交易明細表）
9. `invoice_lottery_rules`（統一發票開獎獎金與中獎規則表）
10. `invoices`（統一發票表）
11. `invoice_items`（發票品項明細表）

---

### 1. 帳戶表（`accounts`）

- **記什麼**：實體與虛擬資金載體，記錄現金皮夾、銀行活存戶、信用卡、券商交割帳戶等。
- **為何單獨成表**：資金必須落於明確載體。所有入帳、花費、移轉與交割必須指向具體帳戶，獨立成表以維護帳戶屬性、幣別、狀態與初始資產。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 帳戶唯一識別碼 |
| `name` | `VARCHAR(100)` | 必填 | UNIQUE | 帳戶名稱（如：國泰世華活存、台新黑狗卡） |
| `account_type` | `VARCHAR(20)` | 必填 | CHECK | 帳戶類型：`cash`（現金）、`bank`（銀行）、`credit_card`（信用卡）、`brokerage`（券商交割戶） |
| `currency` | `CHAR(3)` | 必填 | 無 | 帳戶基準幣別（如：`TWD`、`USD`） |
| `initial_balance` | `NUMERIC(16, 4)` | 必填 | DEFAULT 0.0000 | 開帳初始金額（信用卡通常為 0 或開帳欠款負值） |
| `is_active` | `BOOLEAN` | 必填 | DEFAULT TRUE | 是否在用中（停用後不可進行新記帳） |
| `description` | `VARCHAR(255)` | 可空 | 無 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 約束說明
- PostgreSQL 約束：`CHECK (account_type IN ('cash', 'bank', 'credit_card', 'brokerage'))`。
- PostgreSQL 約束：`UNIQUE (name)`。

---

### 2. 帳戶移轉表（`account_transfers`）

- **記什麼**：資金在兩個內部帳戶之間的流轉事件，如銀行提領現金、帳戶跨行轉帳、銀行扣繳信用卡款、活存存入券商交割戶等。
- **為何單獨成表**：移轉本質是同一資產主體的資金重分配，不是外部收益（入帳），亦非消費損耗（花費）。若拆散成花費加收支將扭曲損益報表，必須以單一移轉事件配對「轉出帳戶」與「轉入帳戶」。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 移轉唯一識別碼 |
| `from_account_id` | `BIGINT` | 必填 | FOREIGN KEY -> `accounts(id)` | 轉出帳戶（刪除限制：RESTRICT） |
| `to_account_id` | `BIGINT` | 必填 | FOREIGN KEY -> `accounts(id)` | 轉入帳戶（刪除限制：RESTRICT） |
| `out_amount` | `NUMERIC(16, 4)` | 必填 | CHECK (> 0) | 轉出金額（以轉出帳戶幣別計） |
| `in_amount` | `NUMERIC(16, 4)` | 必填 | CHECK (> 0) | 轉入金額（以轉入帳戶幣別計，換匯時可不同於轉出金額） |
| `fee` | `NUMERIC(16, 4)` | 必填 | DEFAULT 0, CHECK (>= 0) | 移轉手續費（自轉出帳戶額外扣除） |
| `exchange_rate_to_twd`| `NUMERIC(12, 6)` | 必填 | DEFAULT 1.000000 | 轉出金額折算台幣之匯率 |
| `transferred_at` | `TIMESTAMPTZ` | 必填 | 無 | 移轉發生時間 |
| `note` | `VARCHAR(255)` | 可空 | 無 | 移轉備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 約束說明
- PostgreSQL 約束：`CHECK (from_account_id <> to_account_id)`（轉出帳戶與轉入帳戶不得相同）。
- PostgreSQL 約束：`CHECK (out_amount > 0 AND in_amount > 0 AND fee >= 0)`。
- 業務規則：由 API 在寫入前檢查轉出帳戶與轉入帳戶之 `is_active` 皆必須為 `TRUE`。

---

### 3. 入帳分類表（`income_categories`）

- **記什麼**：收入的商業性質分類，例如薪資、年終獎金、銀行利息、一般退款、投資分紅、發票中獎等。
- **為何單獨成表**：分類是階層管理收支維度的依據；規範要求入帳分類與花費分類必須嚴格分開且名稱獨立不能重複，故各自獨立成表。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 分類唯一識別碼 |
| `name` | `VARCHAR(50)` | 必填 | UNIQUE | 分類名稱（如：薪資、利息、統一發票中獎） |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 約束說明
- PostgreSQL 約束：`UNIQUE (name)`（入帳分類名稱不得重複）。

---

### 4. 入帳記錄表（`incomes`）

- **記什麼**：所有實體資金增加的入帳流水，包括本薪、兼職所得、銀行存款利息、商戶退款、發票對獎中獎入帳、投資現金股利與減資退回款。
- **為何單獨成表**：入帳是資產正向現金流的唯一來源冊子。與花費分開成表符合收入與支出不同的業務生命週期與關聯來源（可對接發票中獎、投資交易分紅）。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 入帳唯一識別碼 |
| `account_id` | `BIGINT` | 必填 | FOREIGN KEY -> `accounts(id)` | 入帳收款帳戶（刪除限制：RESTRICT） |
| `category_id` | `BIGINT` | 必填 | FOREIGN KEY -> `income_categories(id)` | 入帳分類（刪除限制：RESTRICT） |
| `amount` | `NUMERIC(16, 4)` | 必填 | CHECK (> 0) | 入帳金額 |
| `currency` | `CHAR(3)` | 必填 | 無 | 入帳幣別 |
| `exchange_rate_to_twd`| `NUMERIC(12, 6)` | 必填 | DEFAULT 1.000000 | 折合新台幣匯率（台幣為 1） |
| `received_at` | `TIMESTAMPTZ` | 必填 | 無 | 款項入帳時間 |
| `invoice_id` | `BIGINT` | 可空 | UNIQUE, FOREIGN KEY -> `invoices(id)` | 關聯中獎發票（刪除限制：RESTRICT） |
| `investment_transaction_id`| `BIGINT`| 可空 | UNIQUE, FOREIGN KEY -> `investment_transactions(id)` | 關聯投資現金股利或減資交易（刪除限制：RESTRICT） |
| `note` | `VARCHAR(255)` | 可空 | 無 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 約束說明
- PostgreSQL 約束：`CHECK (amount > 0)`。
- PostgreSQL 約束：`CHECK (exchange_rate_to_twd > 0)`。
- PostgreSQL 約束：`UNIQUE (invoice_id)`（一張發票最多只能產生一筆中獎入帳記錄；空值不衝突）。
- PostgreSQL 約束：`UNIQUE (investment_transaction_id)`（一筆現金股利或減資交易最多只能產生一筆入帳記錄；空值不衝突）。
- PostgreSQL 約束：`CHECK (invoice_id IS NULL OR investment_transaction_id IS NULL)`（一筆入帳不可同時既來自發票中獎又來自投資交易）。
- 業務規則：由 API 在寫入前檢查關聯的投資交易類型必須為 `cash_dividend`（現金股利）或 `capital_reduction`（減資），且退回現金大於 0。

### 5. 花費分類表（`expense_categories`）

- **記什麼**：支出的商業性質分類，例如餐飲、交通、房租水電、休閒娛樂、醫療保健等。
- **為何單獨成表**：支出分類與入帳分類在財務統計上具備互斥的意義，分離兩表可維持外鍵完整性並保證名稱在自身領域內唯一。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 分類唯一識別碼 |
| `name` | `VARCHAR(50)` | 必填 | UNIQUE | 分類名稱（如：餐飲食品、日常交通） |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 約束說明
- PostgreSQL 約束：`UNIQUE (name)`（花費分類名稱不得重複）。

---

### 6. 花費記錄表（`expenses`）

- **記什麼**：所有實體資金流出的開銷明細。
- **為何單獨成表**：花費為負向現金流流水帳冊。消費日與信用卡實際扣款日存在時間差，且可能多筆花費共同對應到同一張發票（例如一張超市發票，細拆為「食品」與「清潔用品」兩筆花費），因此獨立成表。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 花費唯一識別碼 |
| `account_id` | `BIGINT` | 必填 | FOREIGN KEY -> `accounts(id)` | 扣款或支付帳戶（刪除限制：RESTRICT） |
| `category_id` | `BIGINT` | 必填 | FOREIGN KEY -> `expense_categories(id)` | 花費分類（刪除限制：RESTRICT） |
| `invoice_id` | `BIGINT` | 可空 | FOREIGN KEY -> `invoices(id)` | 所屬發票（可對到多筆花費；刪除限制：RESTRICT） |
| `amount` | `NUMERIC(16, 4)` | 必填 | CHECK (> 0) | 花費金額 |
| `currency` | `CHAR(3)` | 必填 | 無 | 花費幣別 |
| `exchange_rate_to_twd`| `NUMERIC(12, 6)` | 必填 | DEFAULT 1.000000 | 折合新台幣匯率（台幣為 1） |
| `occurred_at` | `TIMESTAMPTZ` | 必填 | 無 | 消費發生日（刷卡或付現日） |
| `settled_at` | `TIMESTAMPTZ` | 可空 | 無 | 帳戶實際扣款/交割日（信用卡出帳扣款日；若為現金或銀行直扣，可為空或同 `occurred_at`） |
| `note` | `VARCHAR(255)` | 可空 | 無 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 約束說明
- PostgreSQL 約束：`CHECK (amount > 0)`。
- PostgreSQL 約束：`CHECK (exchange_rate_to_twd > 0)`。
- 多對一關聯：外鍵 `invoice_id` 指向 `invoices(id)`，不設唯一約束，允許多筆花費對應同一張發票；花費合計不必等於發票總額。
- 業務規則：由 API 在寫入前檢查若帳戶為非信用卡帳戶（如現金），`settled_at` 預設自動填入等於 `occurred_at`；若為信用卡帳戶，`settled_at` 允許留空或於銀行出帳後更新。

### 7. 投資標的表（`investment_assets`）

- **記什麼**：一檔投資證券或標的基本資料，如股票、ETF、外幣債券等。
- **為何單獨成表**：標的代號、所屬市場與報價幣別為交易明細之母體主檔，獨立管理以避免交易明細重複儲存資產名稱或市場資訊。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 標的唯一識別碼 |
| `symbol` | `VARCHAR(20)` | 必填 | 複合 UNIQUE | 標的代碼（如：`2330`、`AAPL`、`0050`） |
| `market` | `VARCHAR(20)` | 必填 | 複合 UNIQUE | 市場別（如：`TWSE`、`TPEx`、`NYSE`、`NASDAQ`） |
| `name` | `VARCHAR(100)` | 必填 | 無 | 標的繁體中文或英文名稱（如：台積電） |
| `currency` | `CHAR(3)` | 必填 | 無 | 標的交易幣別（如：`TWD`、`USD`） |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 約束說明
- PostgreSQL 約束：`UNIQUE (symbol, market)`（同一市場下的標的代號不能重複）。

---

### 8. 投資交易明細表（`investment_transactions`）

- **記什麼**：針對個別投資標的所發生的所有異動流水，記錄交易類型、異動股數、成交單價、手續費、交易稅及衍生現金。
- **為何單獨成表**：投資持有股數、損益與加權成本隨每一次交易動態推移，必須保留每一筆明細以便精確追溯與重算，不能直接修改資產主檔。

#### 欄位定義
| 欄位名稱 | 型態 | 必填 / 可空 | 重複性 / 約束 | 說明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | 必填 | PRIMARY KEY（資料庫自增） | 交易唯一識別碼 |
| `asset_id` | `BIGINT` | 必填 | FOREIGN KEY -> `investment_assets(id)` | 投資標的（刪除限制：RESTRICT） |
| `account_id` | `BIGINT` | 可空 | FOREIGN KEY -> `accounts(id)` | 款項交割帳戶（配股/分割無資金流時可為空；刪除限制：RESTRICT） |
| `transaction_type` | `VARCHAR(30)` | 必填 | CHECK | 交易種類（詳見下方說明） |
| `transacted_at` | `TIMESTAMPTZ` | 必填 | 無 | 交易執行時間 / 除權息基準日 |
| `shares` | `NUMERIC(16, 4)` | 必填 | DEFAULT 0, CHECK (>= 0) | 股數變動絕對值（賣出亦填正值，由類型決定增減） |
| `unit_price` | `NUMERIC(16, 4)` | 必填 | DEFAULT 0, CHECK (>= 0) | 每股成交價或每股配息金額 |
| `total_cash_amount`| `NUMERIC(16, 4)` | 必填 | DEFAULT 0, CHECK (>= 0) | 交易成交總額或配發退回現金總額 |
| `fee` | `NUMERIC(16, 4)` | 必填 | DEFAULT 0, CHECK (>= 0) | 手續費 |
| `tax` | `NUMERIC(16, 4)` | 必填 | DEFAULT 0, CHECK (>= 0) | 證券交易稅 |
| `ratio` | `NUMERIC(12, 6)` | 必填 | DEFAULT 1.000000 | 比例因子（用於分割、合併、減資；非此類填 1） |
| `exchange_rate_to_twd`| `NUMERIC(12, 6)` | 必填 | DEFAULT 1.000000 | 折合新台幣匯率 |
| `note` | `VARCHAR(255)` | 可空 | 無 | 備註說明 |
| `created_at` | `TIMESTAMPTZ` | 必填 | 資料庫預設 UTC | 資料建立時間 |
| `updated_at` | `TIMESTAMPTZ` | 必填 | 由 API 寫入 | 資料最後更新時間 |

#### 交易種類（`transaction_type`）支援清單
1. `buy`（買進）：增加股數，交割帳戶扣款（`total_cash_amount + fee`）。
2. `sell`（賣出）：減少股數，交割帳戶進款（`total_cash_amount - fee - tax`）。
3. `cash_dividend`（現金股利）：股數不變，發放現金（可於入帳表 `incomes` 產生一筆關聯入帳記錄）。
4. `stock_dividend`（配股）：增加股數，無直接交割現金（交割帳戶為空或金額為 0）。
5. `dividend_reinvestment`（股息再投入）：分配股利並同額自動折算買進新股數。
6. `split`（股票分割）：持股乘上分割比例（`ratio > 1`），股數增加，總成本不變。
7. `reverse_split`（股票合併）：持股縮減（`ratio < 1`），股數減少，總成本不變。
8. `capital_reduction`（減資）：股數縮減，若有退回股東現金，退回款於入帳表 `incomes` 記錄為入帳。

#### 約束說明
- PostgreSQL 約束：
  ```sql
  CHECK (transaction_type IN (
      'buy',
      'sell',
      'cash_dividend',
      'stock_dividend',
      'dividend_reinvestment',
      'split',
      'reverse_split',
      'capital_reduction'
  ))
  ```
- PostgreSQL 約束：`CHECK (shares >= 0 AND unit_price >= 0 AND total_cash_amount >= 0 AND fee >= 0 AND tax >= 0)`。
- **賣出防呆（賣出不得使持有小於 0）**：
  - **由 API 在寫入前檢查**：當後端接收賣出請求時，必須在同一個資料庫交易中，以悲觀鎖（`SELECT ... FOR UPDATE`）鎖定該標的在交易發生日（含）以前的所有交易記錄，計算當前累積可用股數。若可用股數小於本次欲賣出之股數，立即中止交易並拋出業務異常，嚴禁寫入。

### 10. 統一發票表（`invoices`）

- PostgreSQL 約束：`CHECK (total_amount >= 0)`。
- PostgreSQL 約束：`CHECK (lottery_status IN ('pending', 'unwon', 'won'))`。
- 複合唯一約束：`UNIQUE (period_code, invoice_number)`（同一期別內之發票號碼不得重複）。

#### 統一發票期別（`period_code`）由開立日決定之規則
台灣統一發票依規定每兩個月為一期（1-2 月、3-4 月、5-6 月、7-8 月、9-10 月、11-12 月）。期別字串標準格式為西元四碼年份加上兩碼雙數月份 `YYYY-MM`。
- **決定公式**：
  若開立日期為 `issued_at`，令其西元年為 $Y$，月份為 $M$（$1 \le M \le 12$）：
  $$\text{期別雙數月} = \lceil M / 2 \rceil \times 2$$
  將月份格式化為兩碼字串（補零），與年份以破折號連接組合成 `YYYY-MM`。
- **範例對照**：
  - 開立日 `2024-01-15` $\rightarrow$ 月份為 1 $\rightarrow \lceil 1 / 2 \rceil \times 2 = 2 \rightarrow$ 期別為 `2024-02`（1-2 月期）。
  - 開立日 `2024-02-28` $\rightarrow$ 月份為 2 $\rightarrow \lceil 2 / 2 \rceil \times 2 = 2 \rightarrow$ 期別為 `2024-02`（1-2 月期）。
  - 開立日 `2024-03-01` $\rightarrow$ 月份為 3 $\rightarrow \lceil 3 / 2 \rceil \times 2 = 4 \rightarrow$ 期別為 `2024-04`（3-4 月期）。
  - 開立日 `2024-12-31` $\rightarrow$ 月份為 12 $\rightarrow \lceil 12 / 2 \rceil \times 2 = 12 \rightarrow$ 期別為 `2024-12`（11-12 月期）。
- **由 API 在寫入前檢查與賦值**：後端建立發票資料時，一律由傳入之 `issued_at` 依上述公式推導填入 `period_code`，資料庫以 CHECK 約束防護格式合法性。

## 三、 虛擬衍生值之計算邏輯（不存實體欄位）

為維護系統之一致性與會計原則，所有資產餘額與持股數量皆不開立欄位供人為任意改寫，其標準計算邏輯如下：

### 1. 帳戶當前即時餘額（Account Balance）
特定帳戶 $A$ 在指定時間點之可用餘額，由下列 5 個子項目加總算出：
$$
\text{餘額}(A) = \text{初始金額} + \text{入帳總額} - \text{花費總額} + \text{轉入總額} - (\text{轉出總額} + \text{轉出手續費})
$$
各項資料來源列：
1. **初始金額**：`accounts.initial_balance`（帳戶建立時填寫之開帳基底）。
2. **入帳總額**：`incomes` 表中所有 `account_id = A.id` 之 `amount` 總和。
3. **花費總額**：`expenses` 表中所有 `account_id = A.id` 且 `settled_at IS NOT NULL`（已實際扣款）之 `amount` 總和。（未扣款之信用卡花費列入信用卡待繳款，不減損目前現金餘額）。
4. **移轉轉入總額**：`account_transfers` 表中所有 `to_account_id = A.id` 之 `in_amount` 總和。
5. **移轉轉出總額**：`account_transfers` 表中所有 `from_account_id = A.id` 之 `(out_amount + fee)` 總和。

### 2. 投資標的當前持有股數（Holdings / Shares）
特定標的 $S$ 的當前累積持有股數，由 `investment_transactions` 表中所有 `asset_id = S.id` 之記錄依時間順序累加推導：
$$
\text{目前持股數}(S) = \sum \Delta \text{股數}
$$
各交易類型之 $\Delta \text{股數}$ 異動規則：
- `buy`、`stock_dividend`、`dividend_reinvestment`：$+\text{shares}$
- `sell`：$-\text{shares}$
- `split`（分割）：持有股數調整為原有股數 $\times \text{ratio}$
- `reverse_split`（合併）、`capital_reduction`（減資）：持有股數調整為原有股數 $\times \text{ratio}$
- `cash_dividend`（現金股利）：股數無變動（$+0$）

### 3. 投資平均成本（Average Unit Cost）
採用「移動加權平均法（Moving Weighted Average）」依交易時序計算：
1. **買進或配股投入時**：
   $$\text{新平均成本} = \frac{(\text{異動前持股} \times \text{原平均成本}) + \text{本次買進成本（含手續費）}}{\text{異動前持股} + \text{本次新增股數}}$$
2. **股票分割 / 合併 / 減資退現金時**：
   - 分割 / 合併：總成本不變，單位平均成本等於 $\text{總成本} / \text{異動後總持股}$。
   - 減資若退回現金：總成本減去退回現金，新平均成本等於 $(\text{原總成本} - \text{退回金額}) / \text{減資後股數}$。
3. **賣出時**：
   - 單位平均成本維持不變，僅依比例依「原平均成本 $\times$ 賣出股數」扣除總持有成本。
   - 實現損益等於 $\text{賣出淨款項} - (\text{賣出股數} \times \text{賣出當前平均成本})$。
